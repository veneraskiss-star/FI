# FI

Персональное приложение для работы с клиентами, задачами и историей встреч. Русский интерфейс, чёрно-белое оформление, светлая и тёмная темы. SQLite на компьютере пользователя. Основная работа доступна без интернета и аккаунта ChatGPT.

## Скачать FI

Готовая сборка для **Mac с Apple Silicon (M1 и новее)**: [последний релиз](https://github.com/veneraskiss-star/FI/releases/latest). Скачайте архив `FI-…-macOS-arm64.zip`, распакуйте и перенесите FI.app в «Программы». Терминал и Node.js для готовой сборки не нужны. Сборка для Intel пока не выпускается.

У каждого пользователя своя локальная база. В архиве нет клиентов, писем, заметок или подключений разработчика. При первом запуске откройте «Настройки»: подключите **свой ChatGPT**, **свою Яндекс 360 Почту** и **свой календарь**. Для Яндекса используйте пароль приложения с нужным доступом к IMAP/SMTP и CalDAV; пароль от основного аккаунта не нужен. Без подключений клиенты, задачи, ссылки и заметки работают локально.

Приложение пока не подписано Developer ID и не нотарифицировано Apple: это предварительная сборка. На другом Mac macOS может блокировать запуск. Не отключайте системную защиту; для беспрепятственного публичного распространения нужна подпись и нотарификация. Ошибки подключения своего ChatGPT зависят также от доступности входа и модели для аккаунта.

## Запуск на Mac без Терминала

Готовая сборка для Mac с Apple Silicon находится в `release/1.0.59/FI-darwin-arm64/FI.app`.

1. Откройте эту папку в Finder.
2. Дважды щёлкните **FI**. При желании перенесите приложение в «Программы» и добавьте в Dock.
3. Для полного выхода нажмите **⌘Q**. Внутренний локальный сервер завершится вместе с приложением.

Устанавливать Node.js и вводить команды для использования готовой сборки не нужно. Это локальная сборка без Developer ID и нотарификации Apple. Для распространения другим пользователям потребуется подпись/нотарификация; защиты macOS приложение не отключает.

## Данные

Mac-приложение хранит базу отдельно от своего пакета: `~/Library/Application Support/Project Hub/project-hub.sqlite`. Кнопка «Открыть папку локальных данных» находится в окне подключения ChatGPT.

При первом запуске, если база приложения ещё не существует, существующая база из исходного проекта копируется через SQLite Backup. Исходная база остаётся на месте. Существующая база Mac-приложения не перезаписывается. После этого  убраузерный запуск из исходников и Mac-приложение имеют отдельные базы: изменения между ними не синхронизируются.

Обновление приложения не удаляет данные. Не удаляйте папку локальных данных. Пользовательская база исключена из Git и пакета приложения.

Для ручной резервной копии завершите приложение через ⌘Q и сохраните папку данных целиком. Для восстановления сначала сохраните текущую папку отдельно, затем замените её нужной копией при закрытом приложении. На другом Mac перенесите приложение и папку данных. Зашифрованные подключения ChatGPT привязаны к системному хранилищу исходного Mac — на другом компьютере войдите повторно. Интерфейс резервного копирования относится к исходному этапу 2 и пока не реализован.

## Сотрудники, контакты и настройки

«Сотрудники» — отдельный раздел: имя, должность, телефон и почта, поиск и редактирование карточек. Сотрудники доступны при назначении задач. Прежние имена и должности сохранены. Для переименования/удаления занятого исполнителя сначала переназначьте его задачи.

Контакты клиента находятся только в карточке клиента, вкладка «Контакты»: имя, должность, телефон, почта и заметка. Почта и телефон открываются стандартными приложениями Mac. Для архивного клиента контакты доступны только для чтения. Контакты не включаются в контекст ChatGPT.

Шестерёнка «Настройки» открывает общий экран: «Работа с клиентами» (этапы, типы клиентов и записей), оформление, подключение ChatGPT. Все клиенты по умолчанию ведутся владельцем рабочего места. Этапы общие для всех клиентов. Используемые этапы/типы нельзя удалить, пока они указаны в записях.

Контакты клиентов хранятся в SQLite, миграция user_version=2 сохраняет существующие данные. Данные сотрудников и варианты этапов — в project-hub.sqlite.options.json рядом с базой. Для переноса/копирования сохраняйте всю папку данных. Контактные данные сотрудников не включаются в контекст ChatGPT; для назначения передаются только имена.

## Разбор информации через свой ChatGPT

1. В Mac-приложении откройте **Настройки → ChatGPT** → **Продолжить с ChatGPT** и завершите официальный вход в браузере.
2. В карточке клиента нажмите **Добавить информацию с ChatGPT**.
3. Вставьте накопленную сводку, историю проекта, заметки, переписку или расшифровку; можно загрузить `.txt`.
4. Модель выбирается автоматически из доступных. При необходимости раскройте «Модель и дата текста»: поле «Когда был написан текст?» нужно только для слов «завтра»/«через неделю» и может оставаться пустым. При неизвестной дате такие сроки не вычисляются.
5. Откройте раздел **Что будет отправлено вместе с текстом**, затем нажмите **Получить предложения**.
6. Проверьте события по отдельности, их даты, задачи и предлагаемые поля карточки. Выберите нужное, отредактируйте и сохраните.

Из одной сводки можно получить несколько событий с разными датами. Неизвестная дата остаётся пустой; запись будет показана в истории как «Дата не указана». Такая запись не подменяет последнюю датированную активность. Даты, ответственные и факты не должны выдумываться — результат необходимо проверить.

Предложения по этапу, типу и аналитику используют ваши списки. Значения выбираются в выпадающих списках на экране проверки; можно сразу открыть настройку вариантов. Если модель предложила неизвестный вариант, он не выбирается автоматически и требует вашего выбора. Для каждого предложения показывается дословный фрагмент исходного текста.

Существующая история, задачи, текущие поля и каталог вариантов показаны в контексте и отправляются вместе с выбранным текстом только по вашей кнопке. Это помогает избежать повторов и не заменить актуальный этап старым историческим событием. Точные совпадения названия/даты события или названия задачи помечаются как возможные дубликаты и по умолчанию не выбираются. Близкие по смыслу записи проверяйте вручную.

Выбранные изменения сохраняются одной транзакцией. Изменения полей фиксируются сегодняшним временем изменения в ChangeLog, а исторические события — собственными датами в Activity. Дата завершения импортированной выполненной задачи пока фиксируется временем добавления; для исторического завершения с точной датой сохраните соответствующее событие истории.

Для анализа нужен интернет. Учётные данные ChatGPT зашифрованы Electron safeStorage с системной защитой macOS и не передаются в интерфейс, SQLite или Git. История переписок в ChatGPT не запрашивается. Используется ваш план, без автоматического подключения платного API. Доступность и лимиты зависят от аккаунта. Основная работа без ИИ остаётся локальной.

Реальный ответ модели на личном аккаунте должен быть проверен пользователем; автоматические тесты используют только вымышленные данные и не расходуют лимиты.

Официальные спецификации:
- https://developers.openai.com/siwc/token-sharing-open-source/sign-in
- https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference
- https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations

## Разработка

Нужен Node.js 24.15+ и npm. Весь исходный код локален и находится в Git.

```sh
npm ci
npm start
```

Браузерный запуск: http://127.0.0.1:3000, база `data/project-hub.sqlite`. Сервер слушает только `127.0.0.1`. Доступ к ChatGPT доступен только в Mac-приложении. `PORT=3001 npm start` меняет порт, `DB_PATH=/полный/путь/file.sqlite npm start` — базу.

```sh
npm run build
npm test
npm run desktop
npm run package:mac
```

`build` проверяет TypeScript и собирает интерфейс. `desktop` собирает и открывает Electron-версию. `package:mac` создаёт .app для архитектуры текущего Mac, используя официальный Electron. При первой установке runtime может потребоваться `node node_modules/electron/install.js` (если пакетный менеджер не запустил скачивание). При проблемах встроенного загрузчика можно скачать официальный ZIP, проверить SHA-256 по `node_modules/electron/checksums.json` и передать папку с файлом `electron-v<VERSION>-darwin-<ARCH>.zip` через `ELECTRON_ZIP_DIR` упаковщику. Уже готовая .app не скачивает runtime при запуске.

Для изменения иконки: `npm run icon` (macOS, Swift/AppKit, sips, iconutil). Готовые PNG/ICNS входят в Git.

## Структура

- `src/` — React, TypeScript, Tailwind, Radix Dialog, кнопка на шаблоне shadcn/ui, Lucide.
- `server/` — Express, SQLite, локальные API, атомарное сохранение предложений.
- `desktop/` — Electron, изолированный preload, OAuth ChatGPT, перенос базы.
- `shared/` — типы, проверка предложений, обработка потока Responses.
- `scripts/` — сборка, упаковка и иконка.
- `tests/` — API, сохранение после перезапуска, откат/повторы встречи, источники и дубликаты, поток, перенос базы.

Только четыре таблицы: Client, Task, Activity, ChangeLog. Версия схемы в PRAGMA user_version. Миграции должны сохранять данные. Задачи хранятся один раз. Последняя активность вычисляется из истории. Даты завершения и изменения полей сохраняются для будущих отчётов.

Отчёты, Excel и интерфейс резервного копирования — исходный этап 2, который требует отдельного согласования.

## Личное рабочее место

Всех клиентов ведёте вы: выбор аналитика убран. В «Сотрудниках» добавляйте имя и должность исполнителей задач. Прежние исполнители сохранены. ## О клиенте и отчёты

«О клиенте» — постоянная информация о компании, проекте и целях. «Текущее состояние» — что происходит сейчас. Оба поля редактируются через «Изменить клиента». ChatGPT предлагает обновления отдельно и не должен переписывать описание компании из-за очередной встречи; перед сохранением проверьте предложения.

В «Отчёте» выберите одного/нескольких клиентов и период (по умолчанию последние 7 дней), нажмите «Подготовить данные», посмотрите контекст и создайте отчёт через подключённый ChatGPT. Кнопка «Отчёт» в карточке предвыбирает клиента. Назначение — руководителю: общий итог, результаты по каждому клиенту, текущее положение, риски, следующие действия. Текст можно скопировать. Отчёт не меняет карточки.

Для сокращения запроса отправляется срез данных: about/state/risks/этап/состояние, открытые задачи, выполненные задачи за период, события и изменения полей клиента за период. Недатированные события, добавленные за период, помечаются отдельно и не считаются произошедшими за этот период. Даты событий — календарные; временные метки для отбора изменений/выполнения интерпретируются по Москве. Контакты/почта как отдельные сущности и вся остальная история не включаются. Текущие поля отражают дату подготовки, а не исторический конец периода. Если срез превышает 100000 символов, выберите меньше клиентов или короче период; скрытого обрезания нет. Точное число токенов/экономия и скорость не измерялись.

Готовый результат сохраняется локально. Совпадение среза, периода, даты подготовки, модели и версии инструкции позволяет открыть его без запроса к ИИ. Последние 20 сохранённых результатов видны как снимки, включая старые после изменения карточек. Несохранённый из-за конкурентного изменения ответ остаётся на экране для копирования. Если сведения в БД устарели, отчёт их не исправит автоматически. Анализ произвольного текста пока использует прежний полный контекст; сокращение в 1.0.8 относится именно к отчёту.

Миграции SQLite v3 (about) и v4 (ReportCache) сохраняют прежние записи. Excel и интерфейс резервного копирования в этот релиз не входят.

## Копирование и Markdown

В Mac-приложении копирование отчёта использует системный буфер macOS через ограниченный IPC. Рядом находится иконка скачивания: открывает стандартное окно сохранения .md. Файл и копируемый текст содержат заголовок, имена клиентов и период. Браузерный запуск использует браузерный буфер и скачивание файла.

## Яндекс 360 · Календарь

В «Настройки → Яндекс 360 · Календарь» введите рабочую почту и отдельный пароль приложения типа «Календарь», созданный в Яндекс ID. Обычный пароль от аккаунта не нужен. Пароль вводите только в приложении. Подключение проверяет доступ к календарям и сохраняется safeStorage в calendar.enc, отдельно от SQLite. Организация может запретить CalDAV; новый пароль по документации Яндекса иногда начинает действовать через 2–3 часа.

«Календарь» показывает встречи выбранного доступного календаря за период до двух месяцев. Повторения, исключения/переносы и события на весь день поддерживаются. Обновление при открытии, смене периода/календаря и по кнопке; фонового опроса по таймеру нет. Сведения календаря не отправляются в ChatGPT.

Кнопка «Встреча» в карточке клиента открывает форму с клиентом, названием «Встреча · Имя клиента» и кратким описанием. В общем календаре можно выбрать клиента или командную встречу без клиента. Название, описание, время, место и календарь редактируются до явного создания. Участники выбираются из сотрудников и контактов выбранного клиента. При явном создании Яндекс получает список почтовых адресов для приглашений. Существующие встречи отображаются, их редактирование/удаление в Project Hub не добавлялось. Локальная связь с клиентом сохраняется для созданных здесь встреч, автоматического угадывания клиента по чужим встречам нет.

При повторе сохранения одной формы используется тот же UID и If-None-Match, чтобы не создавать дубликат при сетевом сбое. Отключение убирает пароль из локального подключения и не удаляет встречи в Яндексе. Для отзыва доступа полностью удалите пароль приложения в Яндекс ID. Перенос calendar.enc на другой Mac требует повторного подключения.

Реальный корпоративный аккаунт Яндекс 360 ещё не подключался при разработке. Проверки протокола использовали поддельные ответы, визуальная проверка создания — отдельный тестовый календарь.

Официальная инструкция: https://yandex.ru/support/yandex-360/customers/calendar/web/ru/data-exchange/synchronization/sync-desktop

### Исправление подключения 1.0.10

CalDAV в Mac-версии использует Electron net.fetch (системные настройки сети/прокси) вместо Node fetch. Разрешены только перенаправления внутри https://caldav.yandex.ru, до трёх переходов. Таймаут 20 секунд на запрос. Ошибка содержит этап подключения и безопасный сетевой код без пароля/логина/URL. Неверные учётные данные (401) и отсутствие прав (403) отображаются отдельно. Проверка без учётных данных получила ответ 401 через системный стек; успешный вход пользователя ещё не подтверждён.

### Участники и Телемост — 1.0.11

В форме новой встречи нажмите «Выбрать участников». Доступны сотрудники и контакты выбранного клиента, поиск по имени/почте, выбранные участники видны метками. Без почты выбрать человека нельзя; заполните её в его карточке. Одинаковый адрес используется один раз, организатор — подключённая рабочая почта. При смене клиента выбор участников сбрасывается. Кнопка «Создать и пригласить (N)» явно показывает число получателей.

«Создать видеовстречу в Телемосте» включено по умолчанию; для очной встречи снимите галочку. В CalDAV передаётся X-TELEMOST-REQUIRED:TRUE, после PUT событие перечитывается и проверяется X-TELEMOST-CONFERENCE. В списке появляется «Открыть видеовстречу». Если Яндекс не вернул ссылку, не сохранил участников или сообщил ошибку планировщика, появится предупреждение. Повторное создание не запускается автоматически. При ошибке чтения после успешного PUT встреча считается созданной с предупреждением, чтобы избежать дубликатов. Проверка записи участников не является подтверждением доставки писем в почтовый ящик.

Приглашения — ORGANIZER/ATTENDEE с RSVP и SCHEDULE-AGENT=SERVER. Название, время и выбранные адреса передаются в Яндекс только при явном создании. Дополнительные сведения из карточек и контекст ChatGPT в событие автоматически не передаются.

Официальное описание поля Телемоста (примеры Яндекса используют OAuth; работа с конкретным аккаунтом через существующий пароль приложения проверяется пользователем): https://yandex.ru/support/yandex-360/business/admin/ru/security-service-applications

Протокол календарного планирования: https://www.rfc-editor.org/rfc/rfc6638.html

### Локальное сохранение и уведомления — 1.0.15

Календарь также сохраняет последние открытые недели на Mac в зашифрованном виде. При повторном входе они появляются до ответа Яндекса, при сбое не исчезают. Показано время последнего обновления. Для текущей локальной сборки macOS может отказать в системном уведомлении из-за отсутствия полноценной подписи. В таком случае Project Hub показывает собственный компактный баннер справа сверху со звуком, даже когда основное окно не активно. Баннер не забирает фокус, закрывается через 6 секунд; клик открывает входящие. Он не записывается в системный центр уведомлений и не подчиняется его настройкам «Фокусирования». Выключение звука/уведомлений в настройках Project Hub и системная громкость действуют. Кнопка проверки сообщает, какой вариант показан. Проверка резервного баннера в готовой версии выполнена.
