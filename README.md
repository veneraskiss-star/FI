# Project Hub

Локальное рабочее пространство бизнес-аналитика. Клиенты, задачи и история взаимодействий. Первый этап разработки. Интерфейс на русском, светлая и тёмная темы. Нет авторизации, телеметрии или внешних сервисов.

## Установка и запуск

Нужен Node.js 24.15+ (рекомендуется актуальная версия 24 LTS) с модулем `node:sqlite`, npm и Git.

```sh
npm install
npm start
```

Откройте http://127.0.0.1:3000. Сервер слушает только 127.0.0.1. После установки интернет для работы не нужен. Остановка: Ctrl+C в терминале. По умолчанию запускается локальный сервер с Vite.

```sh
npm run build
NODE_ENV=production npm start
```

Второй вариант использует готовую сборку. Проверка: `npm test` (отдельная временная тестовая база, порт 3098).

## Данные и перенос

База создаётся автоматически: `data/project-hub.sqlite`. Не удаляйте папку `data`. Она исключена из Git. Изменение исходного кода и сборка базу не очищают. Для другого порта используйте `PORT=3001 npm start`; для другого пути базы — `DB_PATH=/полный/путь/project-hub.sqlite npm start`.

Для переноса остановите приложение, скопируйте всю папку проекта без `node_modules`, установите Node.js на новом компьютере и выполните `npm ci`, затем `npm start`. Обязательно перенесите папку `data` со всеми её файлами (включая SQLite WAL/SHM, если они остались). Копировать работающую базу обычным копированием не следует.

До появления интерфейса резервного копирования можно после остановки приложения сохранить копию папки `data` в безопасном месте. Восстановление: остановить приложение, сохранить текущую папку отдельно и вернуть нужную копию `data`.

## Структура

- `src/` — React, TypeScript, Tailwind CSS, кнопка по шаблону shadcn/ui, Radix Dialog, Lucide.
- `server/` — Node.js/TypeScript, Express, встроенный SQLite.
- `tests/` — проверка API, связей, журнала и сохранения между запусками.
- `PROJECT_STATE.md`, `TASKS.md`, `AGENTS.md` — состояние и инструкции для продолжения разработки любым разработчиком.

Схема содержит только Client, Task, Activity, ChangeLog. Версия хранится в PRAGMA user_version. Новые миграции должны сохранять существующие данные. Задачи хранятся один раз; сводка и карточки вычисляются из них. Последняя активность определяется по дате записей истории, а не по дате редактирования клиента. Журнал хранит изменения полей и удаление задач/записей, дата выполнения задач сохраняется отдельно.

Отчёты, ExcelJS и интерфейс резервного копирования относятся ко второму этапу и пока не реализованы.
