# Состояние проекта

## FI 1.0.59 — папки заметок и доводка рабочего пространства

Заметки: разделители Markdown отображаются в CodeMirror блоком без изменения исходного текста. Папки и вложенные пути хранятся в NoteFolder, заметка имеет folder. Последовательная миграция v7→v8 сохраняет базу; перемещения защищены ревизией и записываются в NoteChangeLog. Дерево папок сворачивается, поиск/корзина/привязки сохранены. Нижние панели списка и редактора одинаковой высоты, блок использует доступную высоту с прежней прокруткой.

Telegram: кнопка в заметке предлагает сотрудников и контакты привязанного клиента с логином. После явного выбора сохраняется текущий текст, создаётся приватный временный полный .md, файл копируется в macOS pasteboard (NSFilenamesPboardType/public.file-url), открывается только проверенный tg://resolve. Пользователь вставляет ⌘V и отправляет в Telegram. Это ограничение deep links, автоматического вложения/отправки через URL нет. Файлы текущего сеанса удаляются при штатном выходе; после аварийного завершения их может сохранить временная папка macOS. Telegram API/бота/доступа к чатам нет. Проверки на реальную переписку ничего не отправляют.

Ассистент предпочитает доступную GPT-6 Luna; анализ в карточке клиента не менялся. Настройки имеют видимую область раскрытия, отдельную прокрутку контекста. В Кому/Копия/Скрытая копия — локальные подсказки сотрудников, клавиши Up/Down/Enter/Escape; адреса не передаются ИИ. Убрана подпись рабочего пространства, клиенты используют Building2.

Плеер: опрос каждые 2 секунды с автоматическим восстановлением после ошибки и защитой от запоздавших результатов во время управления. Подтверждение паузы ожидается повторными чтениями до ~1.6 секунды, а не ошибкой через 250 мс. Кеш обложек остаётся привязанным к источнику/треку; поддержаны безопасные локальные PNG/JPEG/WebP до 2 МиБ. Внешние обложки не загружаются. Реальный системный адаптер отвечает; активного Now Playing во время проверки не было, живые обложки/переключение пользовательской очереди не проверялись.

Уведомление доступно во fullscreen Spaces через visibleOnFullScreen; не забирает фокус. Выбор дисплея следует видимому окну FI, иначе сохраняется прежнее поведение. Сборка для распространения не включает локальный legacy-path разработчика, базы/письма/учётные данные; инструкция нового пользователя в README. Публикация исходников и скачиваемого релиза GitHub согласована пользователем.

Проверки: 124/124 теста, build и build:desktop успешны; пакет arm64 собран. Изолированный Electron smoke подтверждает запуск с пустой базой. UI на вымышленных данных: разделитель/таблица и прокрутка, сохранение папки после reload, подсказка сотрудника с подстановкой адреса, Luna/смена модели/закрытие параметров при клике в чат, список Telegram. ## FI 1.0.58 — письмо сразу с вложенной заметкой и просмотр без потери черновика

Исправлена связь email-предложения ассистента с заметкой: email.noteIds проверяются по выбранному контексту; при явной просьбе приложить заметку и одном найденном кандидате есть ограниченный fallback, при неоднозначности задаётся вопрос. Планировщик запрашивает и сотрудников, и заметки для комбинированного запроса. Предложение note не подменяет email с вложением. После ответа email-черновик сразу открывается без промежуточной кнопки. Это только локальная подготовка: отправка по-прежнему отдельной явной кнопкой.

Перед подготовкой письма сохраняются черновики заметок и читается полный актуальный текст по ID из Notes API, а не усечённый ИИ-контекст. Удалённые заметки не прикладываются. MailAccount.compose атомарно создаёт отдельный зашифрованный черновик с проверенными полями сообщения и полными .md-файлами; старые письма сохраняются. До пяти заметок, прежние лимиты вложений сохранены, неожиданные ключи message не копируются в хранилище.

Имя .md-вложения в MailComposer — кнопка просмотра. Новый read-only IPC возвращает содержимое именно сохранённого файла из черновика, проверяет аккаунт/ID/расширение/объём; доступа к произвольным путям нет. Вложенный Radix Dialog показывает безопасный Markdown с таблицами и кнопкой «К письму», не размонтируя редактор письма. Перед просмотром сохраняются текущие поля. Получатель, тема, текст и вложения остаются при возврате; просмотр не переключает активный черновик и не меняет источник заметки.

Проверки: 117/117 тестов, build/build:desktop/package успешны, изолированный Electron smoke HUB_SMOKE_READY/SQLite. Тесты проверяют фактический полный Markdown за пределами 3000 символов, сохранение/шифрование вложения и старого черновика, повторное открытие, ошибочные ID и заголовки без создания пустого письма, email.noteIds и отсутствие отдельного note-предложения, уточнение нескольких кандидатов. UI на локальном адаптере: один запрос сразу открывает письмо с выбранным адресом и файлом; предпросмотр показывает полный документ, список и таблицу; возврат сохраняет изменённые тему/текст и вложение. ## FI 1.0.57 — сотрудники и заметки в ассистенте

Автоматический план контекста включает сотрудников и заметки. На первом шаге — имена/должности и названия/привязки заметок, без почтовых адресов и тел заметок; на втором — только выбранные имя/должность/почта и до пяти выбранных текстов (по 3000 символов с флагом усечения). Телефоны, Telegram, фотографии и клиентские контакты не передаются. Поиск по содержимому выполняется локально через ограниченный noteQuery, дополнительные найденные ID проверяются серверным API, корзина исключается. При превышении пяти кандидатов указывается notesOmitted. Перед поиском сохраняются текущие черновики заметок.

Для «напиши Георгию» ИИ выбирает сотрудника и использует его рабочую почту в отдельном проверяемом черновике. Ответ валидируется: получатель должен присутствовать в выбранных сотрудниках либо явном вопросе/прошлых пользовательских репликах. Одноимённые кандидаты сохраняются в контексте для уточнения; без отличительной фамилии, должности или явно указанного адреса предложение письма заменяется вопросом.

Ассистент предлагает открыть найденную заметку, создать новую или добавить текст в конец существующей. ID существующей заметки обязан присутствовать в выбранном контексте, неизвестные ID отклоняются. При одинаковых названиях требуется уточнение клиента/текста. Новая/дополняемая заметка показывается в компактном окне проверки; текст и новое название можно поправить. Дополнение сохраняет исходный Markdown посимвольно, использует актуальную загруженную ревизию и не перезаписывает конфликтующие правки. Сохранение проходит через прежний Notes API/NoteChangeLog; новая схема базы и зависимости не нужны. После сохранения/открытия переход в существующий редактор; привязка к клиенту сохраняется.

Проверки: 115/115 тестов, build/build:desktop/package успешны, изолированный Electron smoke HUB_SMOKE_READY/SQLite. Тесты: ограничение источников/ID, исключение посторонних телефонов и данных, совпадающие имена/уточнение фамилии и роли, неизвестные адреса, ограничение поиска заметок, усечение текстов, одинаковые заголовки, дополнение Markdown и конфликт ревизий. UI на локальном адаптере с вымышленными данными: письмо Георгию с почтой из реального тестового справочника без отправки; локальный поиск по слову «тариф» и открытие нужной заметки; проверка/правка дополнения и сохранение старого + нового текста; новая заметка после редактирования названия и подтверждения открывается в редакторе. Живой ChatGPT и реальные письма не использовались, рабочая база не менялась.

## FI 1.0.56 — редактирование календаря и автоматический контекст ассистента

В карточке события рядом с каждой безопасной HTTPS-ссылкой — копирование в буфер и подтверждение галочкой. Телемост имеет приоритет. Редактирование доступно в календаре с правом записи для организатора/события без другого организатора после получения ETag. Форма предзаполняет название, время, описание, место, участников и клиента; сохраняется исходный CalDAV-ресурс, а не новая встреча. GET + ETag/If-Match защищают от перезаписи параллельных изменений. Для серии создаётся/обновляется только выбранное исключение, сохраняется TZID RECURRENCE-ID; локальная связь серии с клиентом при редактировании отдельной встречи заблокирована. Сохраняются UID, RRULE, VTIMEZONE, VALARM, Телемост и ответы уже приглашённых. После правки инвалидируется локальный кеш календаря, запоздавшие чтения не возвращают старую версию. При старом кеше без ETag нужно обновить календарь.

Ассистент сам выбирает контекст через два последовательных запроса выбранной модели: сначала ограниченный каталог имён/этапов/счётчиков и вопрос/диалог, затем выбранные карточки, задачи или записи истории. План проверяется по разрешённым источникам и ID, до 30 клиентов; чтение ограничено по объёму, пропуски задач/истории обозначаются счётчиками. Нет внешнего фонового подбора. Ручной выбор клиента убран; в параметрах раскрываются последние использованные данные. Почта, контакты и заметки автоматически ИИ не передаются. Подбор добавляет отдельный запрос и задержку; экономия токенов зависит от объёма данных, не гарантируется для маленькой базы. Существующие предложения встречи открывают редактируемую форму календаря; письмо создаётся отдельным локальным зашифрованным черновиком через fresh, старое письмо сохраняется. Создание/отправка — только явной кнопкой подтверждения. При ручной навигации сбрасывается старое предложение встречи.

Для подхода с выбором данных изучены OpenAI Docs: https://developers.openai.com/api/docs/guides/function-calling . Использован существующий Responses-транспорт и валидируемый JSON-план, без новых SDK/зависимостей и без изменения подключения ChatGPT.

Проверки: 111/111 тестов, build/build:desktop/package успешны; изолированный Electron smoke HUB_SMOKE_READY/SQLite. Тесты: исходный ресурс/If-Match, конфликт до PUT и гонка 412, запрет чужого сервера/организатора, сохранение напоминаний/Телемоста/RSVP, отдельные повторения UTC и Moscow TZID, all-day, инвалидирование кеша и запоздалого чтения, безопасные ссылки, валидируемый минимальный контекст и отдельный черновик без сетевой отправки. UI через локальный детерминированный адаптер: копирование ссылки, правка/сохранение события, автоматический выбор только задач нужного клиента, просмотр JSON без остальных полей, подготовка/правка/сохранение письма без отправки, создание встречи только после проверки/подтверждения. Живой ChatGPT и реальные Яндекс-события/письма не использовались; рабочая база не менялась.

Корзина исключается; отвязанные и перенесённые к другому клиенту заметки следуют текущей связи. Схема базы не менялась. Заметки по-прежнему не передаются в ИИ-отчёт автоматически.

## FI 1.0.51 — история редактирования заметок и переносы в ячейках

Command+Z / Command+Shift+Z объединяют изменения текста и таблиц в истории CodeMirror; внутри ячеек и на кнопках таблицы сочетания явно направляются в ту же историю, структурные операции отделены от набора текста. История не сбрасывается при предпросмотре; вне полей ввода сочетания доступны также из панели заметки. Название сохраняет штатную отмену текстового поля. История содержимого относится к текущему сеансу редактора; перезапуск приложения её не сохраняет.

Редактируемая ячейка использует textarea поверх сохранённого измерителя содержимого, фиксированную раскладку столбцов и прежнее оформление: вход в ячейку не меняет геометрию. Shift+Enter добавляет внутренний перенос, Enter сохраняет переход к следующей строке. Переносы сохраняются как <br> в GFM; безопасный Markdown-преобразователь разрешает только простой br без атрибутов, остальные HTML-теги остаются отключены.

Проверки: 98/98 тестов; build/build:desktop/package успешны; изолированный Electron smoke HUB_SMOKE_READY/SQLite. UI на вымышленных данных: таблица до/после фокуса 1069.33 × 163.22 px, Shift+Enter, отмена/повтор ввода, отмена добавленной строки, многострочный предпросмотр. Рабочая база не менялась.
